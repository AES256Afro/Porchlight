# Projects and discussions: plan (2026-11-19)

Goal, in the owner's words: choose a **project folder** for an audit or scan, so that exports and logs land there under clear names. **Reply to a model's answer** inside Porchlight with follow-up questions. Keep those conversations in a **Discussions** section that is still there after the app closes. Show answers **beside the page**, not at the bottom of it. **Parts 2 and 3 are built**: discussions with follow-up questions (invariant 22) and the answers panel (README "Discussions"). Part 1, the project folder, is not. The owner decides what is marked **Decide**.

## Today

- Explain, Summarise and Ask answers are kept only while the page is open (the `kept` map in `cli/ui/assist.js`). Close the app and they are gone. They open under the button, so a long page means scrolling down to read them.
- "Send to a model" answers can be copied or saved as text, one at a time, under a fixed name (invariant 18).
- Exports go through the browser: the Mac app saves them to `~/Downloads` and shows them in Finder.
- Investigations are the exception: each run is kept (0600) under `investigations/` and can be opened again.
- Everything else Porchlight keeps sits beside the report in `~/.porchlight` (or the folder `--report` names).

## Part 1: a project folder

A project is a name and a folder you choose, such as `~/Projects/acme-audit`. Porchlight writes only inside a `Porchlight` folder within it, so it never touches your own files:

```
~/Projects/acme-audit/                     ← you choose this
  Porchlight/                              ← Porchlight writes only in here
    Exports/
      2026-11-19 15.30 Repair roadmap.md
      2026-11-19 15.32 Findings.csv
      2026-11-19 16.05 Cloudflare audit.html
    Discussions/
      2026-11-19 15.40 Explain a finding.md
      2026-11-19 16.10 Cloudflare deeper analysis.md
    Log/
      2026-11-19.log
```

- **Names you can read:** the date, the time and a title from Porchlight's own short list ("Repair roadmap", "Findings", "Explain a finding", "Cloudflare audit"). Which repository or domain a file covers is written at the top of the file. Names never come from scan data or a model's text, so a hostile repository or answer cannot choose a file name (invariant 11). They sort by time.
- **Exports:** Export writes the file to `Exports/` and says "Saved to … · Show in Finder". Download stays available.
- **Log:** one plain-text file a day, recording what Porchlight did in the project: scans started and finished (with counts), exports written, models asked (which model, hosted or not, what kind of question, how long it took), Cloudflare changes applied. It never holds keys, tokens, secret values, emails or the model's text; the text belongs in Discussions.
- **Choosing the folder:** Settings → Projects, or the switcher at the top of the sidebar: "New project", a name, then a folder. You type the folder, or in the Mac app pick it with **Choose…**. Before anything is saved, Porchlight shows exactly what it would create and where, as the scan form's preview does. Only the page on this Mac can choose or change a folder, as with "Access from other devices". Under BoxPilot, the project folders live on the app's data volume.
- **Mac app:** Choose… needs a small bridge from the page to a macOS folder picker. The app has none today. It would hand back a folder path and nothing else.
- **A warning, not a refusal:** if the folder is inside a git repository or a folder you scan, Porchlight says so. Exports name the files where secrets were found, and could otherwise be committed or scanned.

Two ways to take it:

| | A. Output folder | B. Whole workspace |
| --- | --- | --- |
| What goes in the folder | Exports, discussion transcripts and the log | All of A, plus the project's scan report and history, notes, analysis, Cloudflare audit and investigations |
| Switching projects | Changes where files are written | Changes everything the pages show |
| Size of the change | Small: new writer and settings | Large: the server derives every path from one report path at start-up and would need a per-project context |

**Recommendation:** build A first, then B. A answers "where do my exports and logs go" quickly; B makes each project stand on its own.

## Part 2: discussions with follow-up questions

Every model answer starts a discussion, saved as it arrives (0600, beside the report, or in the project).

- **What a discussion keeps:** what kind it is (Explain a finding, Summarise the roadmap, Ask about the scan, Send to a model, Cloudflare analysis); what it was about (the finding, domain or scan, with its date); the model and where it ran; and each turn: your question, the model's answer, the time, and what part of the scan the model saw.
- **Follow-up questions:** type under the answer. Porchlight sends the conversation so far plus your question. Invariant 13 stays as it is. The data is rebuilt by the server from its own report, as for the first question. The page sends only your question and the discussion's id. Earlier answers go back to the model as its own turns. Nothing the model writes is acted on. For a hosted model, the page has already said what leaves your machines.
- **Length:** every follow-up sends the whole conversation again, because model APIs keep nothing between requests. Long discussions cost more, and a small local model loses the start. Porchlight caps a discussion (say 20 turns) and says when it stops.
- **Titles:** Porchlight writes them from what you asked about, never the model: "Explain: AWS access key in api/config.ts (acme-api)", "Ask: Which repository should I fix first?" (your own words, cut to 60 characters), "Cloudflare: deeper analysis of 3 zones". They stay predictable, and hostile scan text cannot rename or bury anything.
- **The Discussions page:** newest first, filtered by kind, model and project, with search. Each discussion opens in full, links back to the finding or domain it is about, and offers Copy as text, Export (escaped, invariant 11) and Delete.
- **A new scan:** a discussion records which scan it was about. Asked a follow-up after a newer scan, it says so. **Decide** whether it carries on with the old data or starts afresh with the new scan.

## Part 3: where answers appear

Answers open in a **panel on the right** that slides in when you press Explain, Ask or Send. It stays open as you move between pages, and can be widened, closed, or opened in full on the Discussions page. Settings → Appearance gets a choice: **Right side** (default), **Below the item** (as today) or **Bottom drawer**. As the rule for looks says, this moves where answers show and never hides a finding. In a narrow window, such as a phone over the tailnet, the panel becomes a full-screen sheet.

## Seeing the conversation in your Claude account too

- Porchlight reaches Claude through the API, with your API key. The API keeps no conversation: each request carries the whole conversation, and nothing shows up in the chat list of the Claude app (web, desktop or phone). The same is true of OpenAI, Gemini, DeepSeek, Ollama and LM Studio.
- The one Anthropic service that keeps a thread you can browse is Managed Agents (in beta). Its sessions can be viewed in the Console and are kept until deleted. But it runs an agent in its own hosted container, bills that session's running time on top of tokens, works only for Claude, and keeps your scan data on Anthropic's side. It does not suit this.
- **Recommendation:** Porchlight keeps the record itself. It works the same for every model and stays on your machine. To take a discussion to Claude, use **Copy for Claude**: the conversation and the data it was about as Markdown, to paste into a Claude chat or Claude Code. **Save to project** writes the same text to `Discussions/`.

## Rules: what stays, what is new

- Invariants 11, 13, 16, 17 and 18 hold as they are. A discussion sits beside a finding and never changes a severity, a count, the roadmap, an export's findings or the CLI's exit code.
- **Invariant 22** (21 is the Cloudflare audit's) now covers discussions. When the project folder is built, it gains: *A project folder is the owner's. Porchlight writes only inside its `Porchlight` subfolder, under names from a fixed list plus the date and time, and the folder is chosen or changed only from the page on this computer.*
